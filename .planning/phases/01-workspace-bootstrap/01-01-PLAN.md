<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner → npm registry | Transitive devDep graph is fetched during install; tampering risk |
| PR author → main branch | Workflow definitions land via PR; malicious action versions could exfiltrate secrets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Tampering | Transitive devDeps | mitigate | Commit `pnpm-lock.yaml` now; CI uses `pnpm install --frozen-lockfile` (wired in plan 01-04). Lockfile pins the full graph. |
| T-1-02 | Tampering | `.github/workflows/ci.yml` action versions | mitigate | Plan 01-04 pins `actions/*` + `pnpm/action-setup` to exact version tags. Re-evaluate to commit SHAs if a compromise is reported. |
| T-1-03 | Elevation of Privilege | Unauthorized npm publish | accept (for Phase 1) | Phase 1 intentionally does NOT wire publish automation. Only `changeset status` runs in CI. Publishing remains manual until a later phase ships a trusted release workflow. |
</threat_model>
